# KakayatoBurmalda — робот-погрузчик, паллеты и сортировка груза

Физический симулятор на Unity 2022.3: робот-погрузчик ездит по ферме, **фиксирует паллеты с грузом
на вилах** и развозит их по зонам сортировки внутри амбара. Груз трёх типов — **ящики**, **бочки**
и **стройматериалы**; за правильную паллету начисляются очки, за чужую — ошибка (и опционально штраф).

## Быстрый старт

1. Откройте проект в Unity **2022.3 LTS**.
2. Сцена соберётся сама при первом открытии Unity (если открыта пустая несохранённая сцена
   без пользовательских объектов). Если автогенерация вам не нужна или сцена уже занята —
   соберите уровень вручную: **Tools → Generate Forklift Demo Scene**.
3. Нажмите **Play**: подъезжайте к паллете вилами, груз защёлкнется сам, отвезите его в амбар
   и опустите/отпустите в нужной зоне (`F`).

## Что генерируется

```
DemoScene
  ├── Ground                        — площадка 90×90 (BoxCollider + трава, слой Ground)
  │     └── Road                    — грунтовая дорога от старта к амбару (декор)
  ├── House                         — фермерский дом: стены с коллайдером, кирпичный поясок,
  │                                    угловые брёвна, окна в рамах со стеклом и подоконником,
  │                                    дверная рама с козырьком, крыша с коньком и подшивкой,
  │                                    труба, крыльцо, бочки
  ├── Barn                          — амбар: стены с коллайдерами, дверная рама въезда (8×6 м)
  │                                    с табличкой, обшивка стен, укосины, свесы, конёк,
  │                                    внутренний каркас, сено, конусы у въезда
  │     ├── SortingZone_Boxes        — зона под ящики (триггер 5×1,8×5) ВНУТРИ амбара
  │     ├── SortingZone_Barrels      — зона под бочки
  │     └── SortingZone_Construction — зона под стройматериалы
  ├── Forklift                      — Rigidbody 900 кг + BoxCollider (низкое трение) +
  │     │                             ForkliftController, тег Forklift
  │     ├── Body / Counterweight / RearTank / Cabin + CabinGlass / OverheadGuard /
  │     │   MastRail×2 + MastCylinder×2 + MastTie×3 / Headlight×2 / Exhaust  — меши без коллайдеров
  │     ├── MastTiltPivot → ForkCarriage          — каретка вил (2 BoxCollider) + меши вил
  │     │        └── ForkRamp                     — скос-заезд на кончиках вил
  │     ├── GroundCheck                           — точка проверки заземления
  │     └── Wheel_FL/FR/RL/RR → Tire + Rim + Hub + Tread  — колесо: шина, диск, ступица, протектор
  ├── ForkliftResetPoint            — точка сброса погрузчика (клавиша R)
  ├── CargoPallets                  — 9 паллет с грузом на улице между домом и амбаром
  │     └── Pallet_<Тип>_NN         — поддон из реек + груз + BoxCollider + CargoPallet + Rigidbody
  ├── GameManager                   — менеджер игры
  ├── GameCanvas                    — HUD: очки, «отсортировано X / N», остаток, ошибки,
  │                                    таймер ММ:СС, панель «Уровень завершён»
  └── Main Camera                   — CameraFollow: плавный вид от третьего лица сзади-сверху
```

Зоны сортировки стоят **внутри амбара** (локальные координаты −7,5 / 0 / +7,5 по X), паллеты —
**на улице** между домом и амбаром, погрузчик — южнее старта, лицом к дому и амбару. Так получается
настоящий маршрут: подъехать к паллете → зафиксировать груз на вилах → поднять → заехать в амбар →
опустить или отпустить (`F`) паллету в своей зоне.

## Модули

| Файл | Назначение |
| --- | --- |
| `Assets/Scripts/ForkliftController.cs` | Физика погрузчика: тяга силой в Ньютонах (`AddRelativeForce` по локальной оси), рулевое управление через `angularVelocity`, подъём/опускание вил, наклон мачты, **физический захват груза (Locking Mechanism)**, визуальные колёса, диагностика движения. |
| `Assets/Scripts/CargoPallet.cs` | Паллета с грузом: `enum CargoType` (None/Boxes/Barrels/Construction), очки, масса, регистрация в менеджере, состояние захвата (`LockTo`/`ReleaseFromLock`), пометка «отсортирован». |
| `Assets/Scripts/SortingZone.cs` | Зона сортировки (`IsTrigger`): целевой **тип груза**, зачёт в `OnTriggerEnter`, отклонение чужой паллеты, события для VFX/звука. |
| `Assets/Scripts/GameManager.cs` | Счётчик отсортированных паллет и очки в консоль, реестр груза, ошибки, события для UI, конец уровня. |
| `Assets/Scripts/CameraFollow.cs` | Камера: **рабочая поза сбоку над вилами** (обе вилы, паллета, груз и дорога в кадре), позиция через `Vector3.SmoothDamp`, курс через `Mathf.SmoothDampAngle`, взгляд через `Quaternion.Slerp`, ограничение по высоте, пресеты позы, сохранение подобранной позы в `EditorPrefs`, `SnapToTarget()`. |
| `Assets/Scripts/CameraSettingsMenu.cs` | Меню настройки камеры по клавише `F1`: окно IMGUI с ползунками смещения, точки взгляда, сглаживаний и FOV, пресеты, сохранение/сброс; пока меню открыто, курсор освобождён, а погрузчик не читает клавиатуру. |
| `Assets/Scripts/UI/GameUIController.cs` | HUD: подписка на события менеджера, очки, прогресс, ошибки, таймер ММ:СС, панель «Уровень завершён» (Unity UI Text и/или TextMeshPro). |
| `Assets/Scripts/Editor/DemoSceneGenerator.cs` | Генератор уровня: ферма, дом, амбар, зоны по типам груза, паллеты с грузом, детализированный погрузчик, HUD, камера, автоматическое назначение всех ссылок, самопроверка сцены и автозапуск при первом открытии Unity. |
| `Assets/Scripts/Editor/DemoSceneAutoBuilder` (в том же файле) | `[InitializeOnLoad]`-обёртка автогенерации: один раз, только на пустой несохранённой сцене, с тумблером в окне генератора. |

Рантайм-скрипты — пространство имён `KakayatoBurmalda.Forklift`,
редакторный генератор — `KakayatoBurmalda.Forklift.EditorTools`.

## Управление

| Клавиша | Действие |
| --- | --- |
| `W` / `S` | вперёд / назад |
| `A` / `D` | поворот влево / вправо |
| `LeftShift` / `LeftCtrl` | подъём / опускание вил |
| `Q` / `E` | наклон мачты вперёд (вилы вниз) / назад (вилы вверх) |
| `F` | захватить груз на вилы / отпустить его |
| `Space` | ручной тормоз (по умолчанию выключен) |
| `R` | сброс погрузчика на стартовую точку |
| `F1` | меню настройки камеры (курсор освобождается, погрузчик не едет, пока меню открыто) |

Ввод читается старым `Input Manager`. Если в проекте включён только новый Input System
(`Active Input Handling = Input System Package`), клавиатура не читается — погрузчик выведет
об этом предупреждение в консоль через секунду после нажатия газа и подскажет решение.
Внешний ввод подаётся через `SetInput(throttle, steer, lift, tilt, handbrake)` / `SetLiftInput()` /
`ClearInput()`, а захват груза — через `GrabCargo()` / `ReleaseCargo()`.

## Захват груза на вилах (Locking Mechanism)

Никакого «подмешивания скорости»: паллета либо свободна, либо физически закреплена на каретке.

* **Обнаружение.** Каждый физический кадр `Physics.OverlapBoxNonAlloc` проверяет объём захвата
  в системе координат каретки (по умолчанию центр `(0; 0,3; 0,45)`, размер `1,6 × 0,9 × 1,7`);
  маска — только слой `Cargo`.
* **Захват.** Паллета в объёме фиксируется автоматически (`autoLockCargo`) или по клавише `F`:
  `Rigidbody` переводится в `isKinematic = true`, паллета становится **ребёнком каретки вил**,
  а взаимные столкновения с погрузчиком выключаются (`Physics.IgnoreCollision`) — груз не толкает
  корпус и не «выстреливает» при подъёме. Дальше паллета плавно доводится до посадочного места
  (`lockAlignDuration = 0,22 с`): низ паллеты ложится ровно на верхнюю плоскость вил.
* **Удержание.** Пока груз зафиксирован, он не дрожит и не соскальзывает на поворотах и кочках:
  физику паллеты ведёт иерархия каретки, а не силы. Масса погрузчика растёт на массу груза
  (`applyCargoWeight`), поэтому с плитами разгон заметно тяжелее.
* **Отпускание.** `F` или **опускание вил в нижнее положение** (после того как груз хотя бы раз
  поднимали на `autoReleaseLiftHeight = 0,3 м`) — `isKinematic` возвращается в `false`, паллета
  отцепляется от каретки и наследует скорость погрузчика, так что выгрузка в зону выглядит
  аккуратно. Пока паллета не покинет объём захвата, автоматически она больше не цепляется
  (иначе выгруженный груз мгновенно прилипал бы обратно).
* **Засчитанный груз.** Если паллету приняла зона сортировки, она отцепляется от вил и
  возвращается в исходного родителя перед удалением.
* **Вилы не «зарываются» в землю.** При захвате груза (магнит) вилы автоматически приподнимаются
  до `forkMinHeight + liftOnLockHeight` (`liftOnLock = true`, `liftOnLockHeight = 0,14 м`) — иначе
  паллета, севшая на вилы у самой земли, упирала бы их в пол. Плюс сама геометрия вил исключена из
  столкновений с землёй (`ignoreGroundCollisionsForForks = true`): `RefreshForkGroundIgnores()`
  вызывает `Physics.IgnoreCollision` для коллайдеров вил и всех коллайдеров слоя `Ground` без
  `Rigidbody`. Скос-заезд поднят над полом на `rampGroundClearance = 0,045 м`, поэтому вилы не
  цепляются за покрытие ни при опускании, ни при въезде под паллету.

## Физика движения: как это работает

* **Тяга — силой, а не ускорением.** Мотор выдаёт `forwardMotorForce = 16 000 Н` (≈17 м/с² для
  900 кг) и `reverseMotorForce = 10 000 Н`, прикладываясь через `AddRelativeForce(Vector3.forward * F)`
  — то есть **строго вдоль локального forward корпуса**, независимо от поворота. По мере набора
  скорости тяга линейно падает, давая плавный «крейсер» (`maxForwardSpeed = 7` м/с).
* **Движение не завязано на ground check.** Тяга и руль умножаются на коэффициент сцепления:
  на земле 100 %, в воздухе `airControl = 25 %`. Даже если проверка заземления ошибётся,
  погрузчик всё равно поедет.
* **Низкое трение днища.** Корпус опирается на пол всей площадью, поэтому в генераторе ему
  назначается `PhysicMaterial` `Demo_Chassis_Slippery` (трение 0,2, `frictionCombine = Minimum`).
* **Ручник по умолчанию выключен**: все входы обнуляются в `Awake` (`handbrakeInput = false`).
* **Проверка заземления — сферический каст по маске слоёв.** `Physics.SphereCastNonAlloc` вниз из
  `GroundCheck`, маска — только слой `Ground` (если маска не назначена, слой ищется по имени
  автоматически). Отбрасываются коллайдеры самого погрузчика, его `Rigidbody` и паллеты.
* **Скос-заезд на вилах.** В кончиках вил смонтирован `ForkRamp` — низкофрикционная наклонная
  пластина (10°): она помогает поддеть паллету, стоящую на земле, до срабатывания захвата.
* **Диагностика.** Если газ нажат, а машина не движется больше секунды, в консоль один раз
  выводится полный отчёт (заземлён/нет, ручник, масса, тяга, маска земли, мотор, скорость,
  груз на вилах и число паллет в объёме захвата). То же самое можно вызвать вручную:
  контекстное меню компонента «Диагностика движения (в консоль)».

## Камера

`CameraFollow` висит на `Main Camera` и живёт **в корне сцены** — иерархия погрузчика её не трясёт.
Позиция догоняется через `Vector3.SmoothDamp`, курс плавно доворачивается за корпусом
(`Mathf.SmoothDampAngle`), взгляд — через `Quaternion.Slerp`, снизу высота ограничена `minHeight`,
при старте камера сразу встаёт на место (`SnapToTarget`, есть и пункт контекстного меню).

**Поза по умолчанию — рабочая: `offset = (1,6; 3,0; 0,6)`, `lookOffset = (−1,6; −2,0; 3,4)`.**
Камера стоит сбоку над вилами и смотрит вперёд-вниз-влево, в район кончиков вил, поэтому в кадре
одновременно: обе вилы и их середина, паллета перед вилами, верх груза и линия горизонта
(дорога). Проверка выполнена расчётом по фактической геометрии модели — `Tools/camera_check.py`
(пересечение луча камеры с коробками корпуса, кабины, решётки, мачты, каретки и вил + проверка
попадания точки в пирамиду обзора, `fieldOfView = 62°`, 16 : 9).

Почему не «сзади-сверху», как было раньше (`(0; 4,6; −8,6)`): из-за спины вилы **структурно
не видны** — линию взгляда перекрывают корпус (меш `Body` тянется до плоскости мачты), кабина,
защитная решётка и поперечины мачты. Расчёт даёт для той позы 0 из 6 контрольных точек
(вилы, паллета, груз), для нынешней — 6 из 6. Ближайшая к объективу деталь в рабочей позе —
верхняя поперечина мачты, 1,07 м; камера нигде не внутри геометрии.

Настройка в игре — **`F1`**: открывается окно с ползунками смещения камеры (X ±8, Y −1…14,
Z −16…4), высоты точки вращения (0…4), точки взгляда, сглаживания позиции/курса, резкости
доворота, минимальной высоты и FOV (30…90). Пока окно открыто, курсор освобождается, а
`ForkliftController.SetControlEnabled(false)` не даёт погрузчику уехать от случайных нажатий;
Escape закрывает окно, при закрытии курсор снова захватывается. Кнопки-пресеты: «Рабочая (видно
вилы)», «Сзади-сверху» (видна машина целиком, вилы закрыты корпусом — для работы с грузом не
подходит), «Высокая» (та же сторона, но выше — обзор площадки). Кнопки «Сохранить» и «Очистить»
(в редакторе) кладут позу в `EditorPrefs`, и её подхватывают и запуск игры, и генерация сцены.

## Материалы и внешний вид

Модели собраны из примитивов, но материалы настроены как разные поверхности (Standard / URP-Lit,
`FindOrCreateMaterial` в генераторе):

* **Металл робота** — крашеная сталь корпуса (`metallic 0,45`, `smoothness 0,55`), графитовые узлы
  (`0,75 / 0,62`), хром цилиндров и выхлопа (`0,95 / 0,85`), резина шин (`0 / 0,12`),
  стекло кабины — полупрозрачное (`0,1 / 0,92`).
* **Дерево и кирпич** — паллеты, каркас амбара, рамы окон, обшивка: `metallic 0`, `smoothness 0,14–0,18`
  (матовые), черепица дома слегка блестит (`0,05 / 0,24`), бетон и картон — полностью матовые.
* **Груз** — картон со скотчем, стальные бочки с обручами, бетонные плиты и блоки.

## Автогенерация сцены

* **Один клик:** `Tools → Generate Forklift Demo Scene`.
* **Окно настроек:** `Tools → Kakayato → Открыть окно генератора демо-сцены` — новая сцена или
  текущая, дом и амбар, количество паллет каждого типа груза, теги/слои/материалы/HUD,
  сохранение сцены в файл, следящая камера.
* **Автозапуск:** `[InitializeOnLoad]`-класс `DemoSceneAutoBuilder` собирает уровень один раз при
  открытии Unity, но только если активная сцена пустая и несохранённая (открытые файлы сцен не
  трогаются). Отключается галочкой «Генерировать при первом запуске Unity», рядом есть кнопка
  «Разрешить автогенерацию заново».
* **Самопроверка:** после генерации `ValidateGeneratedScene` считает паллеты по типам груза и зоны,
  проверяет, что у каждой зоны свой тип, что все три зоны лежат внутри амбара, что ссылки погрузчика
  назначены, что есть `GameManager`, слой `Ground` и `CameraFollow`, и пишет итог в консоль.
* Всё созданное регистрируется в Undo, есть пункт **Tools → Kakayato → Удалить демо-объекты со сцены**.

## Проверки без Unity

В репозитории лежат два скрипта (Python 3, без зависимостей) — они не входят в сборку и нужны,
чтобы ловить ошибки и обосновывать геометрию до запуска редактора:

| Скрипт | Что делает |
| --- | --- |
| `Tools/validate_project.py` | Разбор всех `.cs` из `Assets/`: баланс скобок, BOM, namespace, `#region`/`#if`; имена полей, которые генератор назначает через `SerializedObject`; существование членов у типов проекта и у внешних Unity-типов (`Mathf`, `Debug`, `Input`, `Vector3`, `string`, …); согласованность `string.Format`; поиск несуществующих атрибутов `[Slider]`/`[IntSlider]`; тип аргумента `Undo.AddComponent<T>()`; число и типы аргументов вызовов методов проекта. Запуск с `--selftest` нарочно внедряет шесть ошибок и проверяет, что каждая поймана. |
| `Tools/camera_check.py` | Проверка позы камеры по фактической геометрии: коробочная модель погрузчика из `DemoSceneGenerator`, дефолты и пресеты читаются прямо из `CameraFollow.cs`; пересечение луча камеры с деталями и попадание контрольных точек в пирамиду обзора. `--search` перебирает позы по сетке. |

Важно: это статический анализ, а не компилятор Unity. «Все проверки пройдены» гарантирует, что
в коде нет опечаток перечисленных классов, но не заменяет сборку в Unity.

## Заметки по совместимости

* **`[Slider]` и `[IntSlider]` в Unity не существуют** — это методы `EditorGUILayout.Slider/IntSlider`,
  а не атрибуты. Использование их как атрибутов даёт `CS0246` и уводит проект в Safe Mode, где не
  работает ни один скрипт. В проекте они заменены на штатный `[Range(min, max)]`.
* Шрифт стандартного UI Text — `LegacyRuntime.ttf` (`Arial.ttf` в Unity 2022.2+ бросает исключение).
* TextMeshPro подключается опционально директивой `TMP_PRESENT` (кнопка «Включить поддержку
  TextMeshPro» в окне генератора добавляет её в Scripting Define Symbols).
* Все файлы сохранены в UTF-8 с BOM — иначе кириллица в строках `Debug.Log` ломается на Windows.
* `[RequireComponent(typeof(Rigidbody))]` у `CargoPallet`: паллета без Rigidbody не соберётся —
  это защита от «пропавшей» физики груза.

## Требования

* Unity **2022.3 LTS**; пакеты не требуются (UI-модуль входит в стандартный манифест,
  TextMeshPro — опционален).
